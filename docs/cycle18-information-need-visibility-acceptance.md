## Iteration and failure notes

- The first browser attempt exposed a real UI aggregation defect: a candidate identity was marked seen before a pinned row with null `organic_rank` was discarded, suppressing a later organic occurrence for that identity in the same query. The fixture now locks this edge case; implementation moved the deduplication mark until after pin/rank validation, and the final rerun passed.
- The first package comparison used unscoped `importlib.metadata.version()` and selected globally installed metadata `0.13.1`, even though the target-installed module was `0.16.0`. A target CLI invocation without `PYTHONPATH` also could not import the `--target` package. The final smoke reads distribution metadata from the isolated target path and sets `PYTHONPATH` for the target CLI; module and wheel versions then matched at `0.16.0` and CLI help exited 0. These were harness invocation errors, not a product package failure.
- Final-polish regression checks were added for the observed-query count and cached corpus-index fallback. The first fallback assertion run left the synthetic UI's `#index-name` blank, so the fixture did not provide the expected cached corpus fallback and its rank assertion failed. Seeding the synthetic saved index fixed the fixture setup; the rerun passed against the final source.
- The final result remains synthetic and offline. The two skipped checks and all NOT RUN limits above remain outside the pass claims.
