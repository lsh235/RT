# Cycle 45–48 로드맵: 로컬 개인 지식 MVP

**기준선:** v1.5.0 / Cycle 44, `codex/cycle-44-positive-target-misses` (저장소 README의 기준선 표기 참조)

## 목표와 종료 조건

개발 목표를 무기한 확장하는 방식에서 벗어나, 로컬 단일 계정 사용자가 자기 지식을 등록하고 검색하며 재현 가능한 평가를 할 수 있는 로컬 우선 계정별 직원 지식 튜닝 MVP를 완성한다. 작업은 Cycle 45부터 48까지 네 사이클로 제한한다. **Cycle 48의 모든 종료 게이트가 PASS일 때만 이 MVP를 완료로 닫는다.** 하나라도 FAIL 또는 미검증이면 완료로 표시하지 않고 해당 범위의 해결 계획을 기록한다.

전제는 다음과 같다.

- 기존 로컬 앱 계정 UUID 하나가 staff 소유자 하나를 식별한다. 소유자 식별은 서버 세션에서 유도한다.
- 앱은 loopback/local 범위로 유지한다.
- 계정 소유 개인 지식과 계정별 Elasticsearch BM25/vector/hybrid 코퍼스는 기존의 일반 공유 Elasticsearch 인덱스와 서로 다른 검색 경로다. 공유 인덱스 동작을 개인 코퍼스로 재해석하지 않는다.
- C37은 로컬 계정/비밀번호 세션과 소유자 범위 concepts/runs/AI sessions, C38은 계정 비공개 SQLite 텍스트 지식 CRUD/FTS, C39는 `/api/concepts/tune`과 분리된 개인 concept preview 및 사람 판단을 제공한다. C39의 숫자 가중치는 확장 eligibility에 관여하지만 순위를 조정하지 않는다.
- C42는 서버 유도 namespace와 ACL guard를 둔 계정별 private ES alias/BM25를 추가했고 일반 공유 인덱스 경로는 공유 상태로 유지한다. C43은 소유자 필터가 적용된 private vector/hybrid를 추가했지만 개인 지식 텍스트를 AI context에는 넣지 않으며 production multi-tenant readiness를 주장하지 않는다. C44의 저장된 top-K positive-judgment miss 화면은 synthetic 자료만 사용한 브라우저 증거다.

이 전제는 구현 상태의 요약이며, 각 사이클 종료 시 현재 코드와 acceptance 기록으로 다시 확인한다.

## 네 사이클

### Cycle 45 — 소유권·온보딩·문서 수명주기

계정 UUID와 staff 소유자 경계를 확정하고 첫 사용, 등록, 수정, 삭제, 동기화 상태, 재시도, 마이그레이션 정책을 초보 사용자 흐름으로 정리한다. SQLite 원본과 Elasticsearch 게시 상태가 어긋날 때의 상태 표시와 복구 절차를 문서화한다.

**PASS 기준:** (1) 소유자 ID는 인증 세션에서만 결정되고 요청 본문 값으로 덮어쓸 수 없음을 테스트로 확인한다. (2) 생성·수정·삭제·부분 실패·재시도·마이그레이션 실패 각각에 사용자에게 보이는 상태와 복구 행동이 정의되고 테스트된다. (3) 기존 계정/데이터에 대한 마이그레이션이 반복 실행 가능하며 실패 시 원본을 보존한다. (4) 첫 사용부터 개인 코퍼스 동기화까지의 도움말이 실제 UI와 일치한다.

### Cycle 46 — 초보자용 개인 지식 전체 흐름

개인 지식 등록 → 색인 상태 확인 → 검색 → 결과/근거 확인까지 이어지는 로컬 흐름을 완성한다. 개인 검색과 일반 공유 인덱스 검색의 선택·결과를 분명하게 표시하고, 개인 문서의 출처와 검색 lane을 결과에 남긴다.

**PASS 기준:** (1) 신규 빈 계정과 지식이 있는 계정 각각에서 등록부터 결과 확인까지 브라우저 E2E가 재현된다. (2) BM25/vector/hybrid 선택이 개인 lane에서 작동하고, 각 결과에 문서 출처와 사용한 lane이 표시된다. (3) 계정 A의 fixture 자료가 계정 B의 검색/문서 조회 결과에 나타나지 않으며, 일반 공유 lane은 기존 동작을 유지한다. (4) 색인 지연·실패·부분 성공 상태가 성공으로 오인되지 않고 복구 가능하다. UI mock만으로 이 기준을 닫지 않는다.

### Cycle 47 — 개인 지식 평가와 재현 가능한 튜닝

개인 코퍼스용 계정 범위 평가를 추가한다. 질의/관련 문서 판단을 저장하고 학습·검증 데이터를 분리하여 검색 설정을 비교한다. 저장된 run에는 데이터 식별자, 분할, 설정, 모델/임베딩 및 코퍼스 상태를 재현에 필요한 수준으로 기록한다. 현재 이미 제공된 기능이라고 간주하지 않는다.

**PASS 기준:** (1) 평가 데이터와 각 저장 run이 소유자에 귀속되고 타 계정에서 열리지 않는다. (2) train/validation 분할이 문서화되고 누수가 없는지 fixture 기반 테스트가 확인한다. (3) 동일한 고정 fixture와 설정으로 두 번 실행했을 때 결과와 설정 기록이 재현되며, 기준선 대비 지표와 질의별 결과를 확인할 수 있다. (4) tuning은 validation 결과를 보고하고 자동으로 production급 품질을 선언하지 않는다. (5) 실제 Elasticsearch가 없는 테스트는 mock/fixture로 명시한다.

### Cycle 48 — 경계 검토·복구·회귀·종료

계정 간 접근 경로, 공유/개인 lane 분리, 실패 및 복구, 회귀, 대표 코퍼스 E2E를 종합 검토한다. 문서와 버전 기록을 정리하고 Cycle 45–48 acceptance 결과를 한 곳에서 추적한다.

**PASS 기준:** (1) 개인 지식의 검색·문서·설명·진단·평가 경로에서 위조한 계정/alias 값과 타 계정 식별자 접근을 거부하는 자동 검증이 모두 통과한다. (2) 색인 중단, 부분 실패, 재시작 후 복구, 재시도에서 원본 보존 및 명확한 상태가 확인된다. (3) 전체 회귀와 대표 코퍼스 E2E가 통과하고 실행 명령·환경·결과를 기록한다. (4) README/사용 문서/API 계약/버전 정보가 실제 동작과 일치한다. (5) 모든 C45–C48 게이트가 판정 가능하며 PASS 또는 명시적인 NOT RUN 사유가 추적된다. 단, 필수 게이트를 NOT RUN으로 남기면 MVP 완료 판정은 보류한다.

## 증거와 주장 경계

- 실제 대표성 있고 안전하게 사용할 수 있는 코퍼스가 제공되지 않으면 **live corpus tests는 NOT RUN**으로 기록한다. 빈 fixture나 synthetic 자료로 실제 검색 품질을 증명하지 않는다.
- mock 및 synthetic 테스트는 계약, 분기, UI 동작 증거다. 실제 Elasticsearch 동작이나 검색 품질의 증거가 아니다. 실제 코퍼스와 클러스터가 주어지면 결과, 설정, 코퍼스/임베딩 상태를 함께 보존한다.
- 이 범위는 답변 생성, 개인 지식의 AI context 주입, 실제 회사 배포, production readiness 또는 완전한 보안 보증을 포함하지 않는다. 기존 ACL 경계는 검증 대상이지 보안 인증이 아니다.
- 모델/도구 runtime identity는 실행 환경이 관측 가능한 경우에만 기록한다. 선언된 요청 설정만으로 실제 runtime identity를 확인했다고 쓰지 않는다. 현재 이 문서 작성 세션에서 runtime identity는 **관측/검증되지 않음**이다.

## 범위 조정 메모

개인 문서를 AI context에 넣기, 임의의 공유 인덱스 문서를 개인 계정에 배정하거나 필터링하기, loopback 밖 회사 환경에 배포하기는 이 MVP의 추가 요구다. 각각 권한·검색 의미·데이터 수명주기·운영 검증 범위가 넓어지므로 별도 추정과 승인된 로드맵이 필요하다. 이에 따라 일정은 **최소 Cycle 49 또는 C50–C53 이상**으로 연장될 수 있다. 이 작업을 C45–C48에 묵시적으로 포함하지 않는다.

## 사이클 운영 규칙

- 각 사이클 시작 시 현재 기준선과 작업 트리를 확인하고, 변경이 잦을 수 있는 동작·호환성은 공식 문서나 1차 출처를 우선 조사한다. 근거 URL과 확인 날짜를 사이클 기록에 남긴다.
- 구현과 테스트 작업은 `gpt-6-luna` 서브에이전트에 명시적인 파일/책임 범위를 부여해 맡긴다. 조정자는 범위와 근거를 검토하고 각 acceptance 항목을 **PASS / FAIL / NOT RUN**으로 판정한다. 이 문서만으로 현재 또는 과거 실행의 실제 모델 runtime identity가 확인되었다고 보지 않으며, 관측 가능한 경우에만 기록한다.
- 필수 게이트가 실패하면 해당 사이클은 닫지 않고 수정 작업으로 되돌린 뒤 재검증한다. 모든 게이트가 PASS인 사이클만 SemVer 커밋과 annotated tag로 마감한다.
- 사용자의 데이터와 무관한 변경을 보존한다. PR이나 GitHub Release는 별도 요청이 있을 때만 진행한다. 이 로드맵 및 계획 자료의 업로드는 제품 기능 완성이나 제품 릴리스 완료를 뜻하지 않는다.
