# Agent SDK research and safety decisions

Research checked 2026-10-18 against the linked official documentation and local SDK packages. The implementation uses subscription sign-in through each provider's SDK; it does not provision API keys or read provider credential files.

## Findings and decisions

| Source | Documented behavior | Design implication and boundary |
|---|---|---|
| [OpenAI Codex SDK](https://learn.chatgpt.com/docs/codex-sdk) | The Python SDK (`openai-codex`) wraps the Codex app-server and includes a pinned CLI runtime. Python support starts at 3.10. An omitted model uses the configured/recommended default. | Use the SDK's configured ChatGPT sign-in and default model; do not copy desktop chat state. The installed package here is `openai-codex 0.163.0` (bundled CLI 0.163.0). Subscription usage is plan- and usage-limited, not unlimited; [current plan usage](https://learn.chatgpt.com/docs/usage) can vary by plan and workload. |
| [Codex app-server](https://learn.chatgpt.com/docs/app-server) and [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) | Tool availability is controlled by runtime configuration. Shell/unified execution, apps, web search, browser/computer features, image viewing, and configured MCP servers have separate controls; MCP server tables are allowlists and individual servers can be disabled. `forced_login_method="chatgpt"` selects the subscription sign-in mode. Read-only sandboxing and denied approvals alone do not imply that every discovery tool is absent. | Run in a disposable, isolated working directory with read-only sandbox, deny-all approvals, ChatGPT-only forced login, shell/unified execution/apps/browser/computer/image viewing/web/multi-agent features disabled, and each configured MCP name explicitly disabled. Permit only the two observed inert Codex resource-discovery calls if each result is successfully parsed and contains zero resources/templates. Reject every other native tool, server, event, malformed result, or nonempty discovery result. This is an explicit metadata-only exception, not permission to use Codex native data tools. |
| [GitHub Copilot SDK authentication](https://docs.github.com/en/copilot/how-tos/copilot-sdk/auth/authenticate) and [Python SDK](https://github.com/github/copilot-sdk/blob/main/python/README.md) | The SDK uses the signed-in GitHub/Copilot account. Python SDK package `github-copilot-sdk` supports Python 3.11+ and has an empty mode for disabling built-in tools. | Use authenticated subscription access, `mode="empty"`, no native/custom provider tools, no host permission grants, and only the host's bounded read-only intent tools. Local package tested: `github-copilot-sdk 1.0.22`. Report authentication and actual inference separately; a successful auth status is not proof that inference works. |
| [Copilot session persistence](https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/session-persistence) | SDK sessions can be created, resumed, disconnected, and permanently deleted. Session history belongs to the SDK session. | Create an app-scoped conversation with an opaque app session ID. It is not a continuation of a user's existing Codex desktop or Copilot chat. Reset should delete provider session state where supported and clear app history. A session must be initialized by a real first turn before relying on cross-client resume; test the exact lifecycle. |
| [Copilot models](https://docs.github.com/en/copilot/concepts/models/overview) | Copilot `auto` selects a provider model based on task and availability. | Default to `auto`; do not present arbitrary model names as supported. Expose explicit choices only from a verified current SDK catalog. The tested empty-mode SDK catalog returned no entries even though `auto` was accepted, so a model picker is not currently evidence-backed. |
| [Elasticsearch search templates](https://www.elastic.co/guide/en/elasticsearch/reference/current/search-template.html) | Search templates use Mustache and support rendering before execution. | Treat rendered query JSON and actual search parity as an acceptance gate. The local test exposed that `toJson` on a scalar generated an unquoted value for this template path; implementation now uses a quoted Mustache variable and must be checked with quotes, slashes, newlines, and braces in input. |

## Tested SDK observations

- The Codex provider probe uses SDK-bundled 0.163.0, checks app-server account root type `chatgpt`, and forces `forced_login_method="chatgpt"`; it reported a default model and seven available models. No auth file, token, login name, or environment secret was read or emitted. A malicious synthetic prompt for file, shell, valid image, browser, and MCP access produced only two Codex resource-discovery calls; both were parsed as empty lists and passed `_guard_codex_result`. The synthetic file value did not appear in the final. The live app route passed three consecutive runs plus the combined current suite: first turn, second turn on the same session, cancellation after a completed host preview, successful retry, and reset/archive. App reset archives the Codex thread; provider-side archived history may remain in the user's account even though local app history is cleared.
- The Copilot SDK account status reported authenticated, and actual inference succeeded using `model="auto"`. The tested package is `github-copilot-sdk 1.0.22`. After lazy provider session creation and reset-race handling, the current live suite passed create → message/inference → history → reset. This is a local signed-in account proof for the tested call, not a quota or availability guarantee.
- These are provider SDK probes, not evidence of unlimited subscription capacity, general availability, quality, or production delivery. Rate limits, subscription eligibility, provider service status, and model availability can change.

## Scope boundary

The AI may draft and explain, but only the app host validates structured output and executes its finite read-only Elasticsearch actions. It cannot write Elasticsearch, grade results, save/tune a profile, access arbitrary HTTP/DSL, read files, run commands, or deploy a profile. Corpus excerpts are untrusted evidence; credentials and provider/account identifiers must not enter prompts, local history, run records, or exports. A human reviews and explicitly adopts any draft.
