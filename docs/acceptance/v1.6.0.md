## Changes and failure diagnosis

- Renamed the live suite to `tests/live_concept_acceptance.py`; default offline discovery selects only `test_*.py`, while live selection requires `ES_RAG_RUN_LIVE=1` and an explicit Elasticsearch URL.
- Fixed the prior 403 path by using an authenticated cookie session, same-origin `Origin`, and CSRF token. After an app restart rotates the process-local CSRF key, the test reacquires the session token.
- Added pinned development/browser dependencies, a clean wheel smoke, contributor/changelog guidance, CI definitions, and a read-only `doctor` CLI.
- The first independent documented browser run failed because it selected system Python. The launcher and guide were corrected in round 2; the documented command then passed. In round 3, the stale static UI fallback was corrected and the browser check now asserts both the first-render and fetched version.

## Safety and evidence boundaries

- The independent live suite used only its own container, volume, and UUID-named fixture index. Its reference source index did not exist, so source-corpus preservation could not be measured there.
- An earlier implementer exploratory run did contact the pre-existing local Elasticsearch service on port 9200. The worker reported that it created/deleted only uniquely named test indices, the configured source index fingerprint matched before and after, and no service/container/volume was stopped or changed. It did not capture every successful fixture name; it separately reported deleting one startup-failure leftover, `concept-accept-f86b8f75b8a9`. This run is not used as independent acceptance evidence. The independent task-owned run above is the R01 live gate evidence.
- The three existing user files were never assigned to a worker or staged. Their initial hashes are unavailable, so this record does not claim a byte-for-byte comparison.
- The requested code license is Apache-2.0. Rights to redistribute the bundled Jira sample corpus remain unresolved and are tracked separately in `docs/release/third-party-asset-audit.md`; this R01 pass is not a public release or a data-rights determination.
- The codebase-memory graph tools were unavailable. Structural exploration used source/file inspection; graph freshness and coverage remain NOT RUN, as recorded in the roadmap.

## Decision

The limitations above remain explicit and do not represent a general relevance-quality result, a live-provider result, a GitHub-hosted CI result, or a redistribution-rights conclusion.
