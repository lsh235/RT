## User problem and fixed scope

Before R05, an account could import and edit private documents, but chunking used fixed codepoint slices and indexing ran as one blocking operation. A user could not inspect token-aware chunk boundaries or reliably resume a long private reindex after cancellation, process restart, or Elasticsearch bulk failure.

R05 adds configurable character, paragraph, and tokenizer-backed chunking to the authenticated personal corpus; inspectable source offsets and counts; and a persisted, cancellable, retryable reindex job that stages a new private Elasticsearch generation and verifies it before alias replacement. The source documents remain authoritative in the account's local SQLite database. The shared Elasticsearch search path and arbitrary shared indexes are outside this work.

Cycle 45–48 mapping: R05 contributes to Cycle 45's edit/delete, partial failure, retry, recovery, migration, and visible-status criteria; it contributes infrastructure to Cycle 46 but does not claim the full beginner search journey. It does not close Cycle 45–48 as a whole.

## API and state contract to preserve

- `POST /api/knowledge/chunks/preview` is read-only. It accepts source text plus a strategy (`character`, `paragraph`, or `token`) and bounded size/overlap settings. Results expose 0-based half-open source offsets, chunk ordinals, exact source text, and real tokenizer counts/identity when available. Token strategy fails clearly when its pinned tokenizer is unavailable; it never silently substitutes words or characters.
- A re-chunk/reindex request is account-scoped and targets only that account's server-derived `esrag-private-<owner>` alias. It returns a job ID. Status reports state, completed/total work, per-document failures, generation, and a safe actionable message. Cancel, retry, and status requests derive ownership from the authenticated session; payload owner IDs and aliases are ignored or rejected.
- Job states distinguish queued, running, cancelling, cancelled, failed/interrupted, and complete. The stored state survives process restart. Retry has a documented deterministic policy and does not claim an old Elasticsearch generation is current while local chunks and the alias differ.
- A candidate generation is staged under an owned generation name, refreshed, and checked for expected document/chunk visibility and identity before the alias changes. Cancellation, bulk failure, stale source fingerprint, or verification failure must leave the previous alias target intact. An empty corpus removes only the authenticated account's alias target after validation.
- Chunk IDs bind the account-local document ID, source revision, policy fingerprint, and slice identity. Source offsets cover the original text with no missing ranges; any intentional overlap is explicit and measurable. Old chunks from edited/deleted documents do not appear in the active alias after a successful sync.
- Per-document policy/config metadata and chunk metadata are versioned/migrated without losing imported source rows or judgments. Migration failure preserves the original DB and allows a safe retry.

The shared code interface is owned by the chunking/storage work package: `chunking.normalize_policy(value)`, `chunking.split_text(text, policy, *, tokenizer=None)`, `chunking.policy_fingerprint(policy)`, and `chunking.tokenizer_info()`. `split_text` returns `ordinal`, `start_offset`, `end_offset`, `content`, and `token_count` (`null` only when the optional exact tokenizer is unavailable for a non-token strategy). Token strategy requires the real pinned tokenizer and does not accept the test injection in live use. State migration v3 adds `source_revision`, `policy_sha256`, and nullable `token_count` to chunks; a singleton `knowledge_chunk_policy`; and `knowledge_reindex_jobs` with `id`, `state`, `policy_json`, `policy_sha256`, `created_at`, `updated_at`, `total_documents`, `completed_documents`, `failed_documents_json`, `source_fingerprint`, `target_generation`, `safe_error`, and `cancel_requested`. Existing chunks remain searchable and are marked with their known legacy/default policy until an explicit re-chunk job replaces them.

## Evidence limits

The R04 task-owned ES flow used one synthetic document and established only a private BM25 lifecycle smoke check. R05 live indexing and recovery checks also used synthetic documents; they establish lifecycle behavior only and do not establish representative retrieval quality. Representative retrieval quality is NOT RUN in R05. No quality gain may be claimed without the later versioned, judged evaluation corpus. Production multi-tenant security, shared-index mutation, AI context injection, and arbitrary vector stores remain out of scope.

The installed `codebase-memory` skill was used to check structural exploration, but graph tools are unavailable in this session. Graph freshness and coverage remain NOT RUN; direct source and `rg` inspection is the fallback. Relevant Cycle 45–48 requirements remain in `docs/cycle45-48-roadmap.md`.
