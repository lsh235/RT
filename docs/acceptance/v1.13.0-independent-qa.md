## Live synthetic Elasticsearch evidence

Disposable index `r08-eval-92f54b3034` contained four fabricated documents with `summary`, `error_signature`, `status`, and a valid nested `comments` mapping. Three records had `status=Open`; the final-test record had `status=Closed`. The validation set had two synthetic queries and five qrels: numeric grades 3 and 1, one explicit-null judgment, and a deliberately absent grade-3 target for miss accounting. Each run requested BM25, `size=10`, `candidate_pool=10`, `cutoff=5`, filter `status=Open`, `rank_constant=60`, and `rerank=false`.

- Run A (`summary=20`, `error_signature=0` with remaining default boosts): query `val-cobalt` returned concrete identity `(r08-eval-92f54b3034,left)` at rank 1, raw BM25 23.705181 (grade 3); `(…,unjudged)` at rank 2, 21.996273 (explicit-null); `(…,right)` at rank 3, 7.473189 (grade 1). Metrics: P@5 0.5, Recall@5 1.0, MRR@5 1.0, nDCG@5 1.0, judged coverage 2/3.
- Run B (`summary=0`, `error_signature=20` with remaining default boosts): `right` ranked 1, 16.309343 (grade 1); `unjudged` ranked 2, 15.098254 (explicit-null); known-relevant `left` was missed. Metrics: P@5 0.0, Recall@5 0.0, MRR@5 0.0, nDCG@5 0.1310456304, judged coverage 1/2; missed list included concrete `(r08-eval-92f54b3034,left)`, grade 3.
- For `val-miss`, both runs returned one absent-qrel synthetic candidate, counted the known grade-3 `(index,never-indexed)` qrel as missed, and reported Recall/MRR/nDCG 0.0 (not unavailable) after the fix.
- `compare_runs` returned zero failed queries. For `val-cobalt`, B-vs-A metric deltas were P `-0.5`, Recall `-1.0`, MRR `-1.0`, nDCG `-0.8689543696`, coverage `-0.1666667`, all five metrics were marked regressions, and the added miss was `(r08-eval-92f54b3034,left,grade 3)`. ## Metrics finding and independent retest

Before the coordinator's R08 fix, the direct case with one known grade-3 qrel, one returned absent-qrel hit, and no returned relevant hit produced Recall `0.0`, nDCG `0.0`, but MRR `null` without a no-positive reason. That was inconsistent with the documented first-relevant-rank metric for a query that has known positive judgments. I reported the precise case and did not edit product code.

After the coordinator fix, I independently reran the same edge case: Recall/MRR/nDCG all returned `0.0`, with no MRR unavailable reason. A zero-positive qrel case still returned Recall/MRR/nDCG `null` and the explicit no-positive unavailable reason. The reference matrix now includes `missed_relevant`; `tests/test_evaluation_datasets_acceptance.py` passed 10/10, including the owner-isolation test. This initial issue is closed for the tested working-tree revision; no R08 defect remains from this finding.
