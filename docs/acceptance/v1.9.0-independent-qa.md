## Required revision behavior reproduction

With a fresh temporary DB and one CSV record (body held constant):

1. First import created the record at revision 1.
2. Identical reimport returned `unchanged`, revision 1 (expected).
3. Reimport with the same source identity/body but changed title and source label returned `replaced`, still revision 1 (fails the v1.9.0 requirement that changed replacement increments revision).
4. Reimport after that returned `unchanged`, revision 1, confirming changed metadata persisted while version identity did not advance.
5. Reimport from a changed filename/source identity with same body returned `replaced`, still revision 1.
6. Direct document edit changing title/source label but keeping body identical stored revision 1.

Probe JSON: `metadata-revision-check.json`, SHA256 `dc48231d91cd927aa50962faef028606a854e106dffbb606eae10fd6758a5ed1`. In `knowledge.py:400-412`, replacement compares title/source/provenance/body tuples to detect changes, but computes increment only from content inequality. In `knowledge.py:177-180`, `save_document` also treats body-only differences as revision changes. Per root's interpretation of the R04 lifecycle requirement, a revision versions the full document metadata/content state; metadata-only edits/replacements must increment. Gate 3 therefore fails.
