## Fix/retest history and limitations

Two harness/regression conflicts were reported and corrected in counted R10 retest rounds; neither required an application behavior change from QA:

1. The first revised offline runner invoked pytest with an absolute tests path but did not expose the repository root, so collection failed with `ModuleNotFoundError: No module named 'examples'`. After the coordinator fixed root import visibility, the exact runner passed.
2. The full pytest collection then found one legacy doctor assertion expecting a sensitive URL path in output. This conflicted with the fixed R10 origin-only diagnostic contract. After that test expectation was updated, the final offline runner passed 301 tests with 1 skipped.

The profile-export artifact in the live example was created by calling `concepts.export_profile` directly with the disposable DB and live ES mapping; the authenticated API route is separately exercised by the account/auth acceptance suite. The ES container had security disabled, so no secured-cluster authentication claim is made. Synthetic Basic credentials were supplied only via environment variables and verified on the request boundary; no credential markers appeared in exported files or output. No external qrels or third-party source content was used.

The inherited sourced-quality evaluation remains **NOT RUN** for lack of permission-cleared representative corpus/qrels. This R10 report makes no retrieval-quality claim.
