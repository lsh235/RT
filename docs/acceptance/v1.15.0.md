# v1.15.0 R10 acceptance — external handoff and bounded operations

Status: **Scope fixed; implementation in progress**
Date: 2026-10-19
Branch: `codex/oss-readiness-v1-16`
Baseline: annotated `v1.14.0` at `5ffb1b3559f01ecded86eff49a4f57aaf047026f`

## User outcome

An Elasticsearch/RAG developer can take a saved profile and measured experiment evidence into a separate local program, create a bounded and reviewable retrieval-context artifact, gather useful diagnostics without sharing credentials, and measure a small fixed concurrency envelope. Local SQLite backup/restore remains explicit and verifiable. This stage does not add answer generation, automatic external calls, private-knowledge-to-AI context, or a retrieval-quality claim.

## Fixed scope

1. Provide a runnable external Python example that consumes an exported `es-rag-profile-v1`, reads connection credentials only from environment variables at runtime, and returns inspectable search results.
2. Provide an explicit retrieval-context bundle helper for those results. It deduplicates only exact `(index, document_id)` identities, keeps first/best rank and provenance, accepts an injected named token counter, includes only whole entries within a bounded budget, and reports the counter identity and included/omitted counts. It must fail closed if a counter or required identity is missing. The helper does not send requests to an answer-generation provider.
3. Preserve the existing versioned saved-run export and fingerprints; verify repeatability and ownership/privacy boundaries without claiming that an artifact re-runs search or proves relevance.
4. Harden the read-only Elasticsearch doctor so successful and failed output cannot disclose URL userinfo, query/fragment values, authorization material, or sensitive URL paths. Keep useful distribution/version/feature estimates.
5. Add a read-only external-runtime measurement example with fixed concurrency choices 1, 2, and 4, bounded iterations, aggregate p50/p95/throughput, and secret/query/document-content-free output. It must not mutate an index or create unbounded workers.
6. Revalidate current explicit SQLite backup/restore behavior using disposable databases, including corruption/rejection and unchanged-destination cases. This is an audit and regression gate; do not replace the established implementation without a demonstrated defect.
7. Update English/Korean user and developer documentation for install, profile handoff, context-bundle limits, credentials, diagnostics, measurements, and backup boundaries.

Third-party source documents and human relevance judgments are not added or redistributed by this stage. The 25-document gRPC fixture is not a quality benchmark. Existing user services on ports 9200 and 8765 remain untouched; any live validation must use a task-owned disposable Elasticsearch instance, synthetic documents, temporary databases, and unique ports.

## Evidence boundaries

- A context bundle is an explicit local export of selected search snippets and document IDs. It is not a generated answer, permission grant, or guarantee that the receiving application handles data safely.
- Token counts are meaningful only for the caller-supplied counter identified in the artifact. Do not label them as another model's token usage.
- Context artifacts may contain user queries, snippets, document IDs, and index names. They require review before sharing. Credentials, authorization headers, local database paths, and full source bodies are excluded.
- The runtime example uses the exported shared-index search profile. Account-private knowledge is not passed into external AI context by this release.
- The bounded measurement is synthetic and specific to the tested local machine and disposable Elasticsearch setup. It cannot establish production capacity or retrieval relevance.
- Existing explicit SQLite backup/restore is per-file and excludes Elasticsearch indices; no cross-file point-in-time snapshot is claimed.
- The inherited sourced-quality gate remains **NOT RUN** because permission-cleared representative human judgments have not been supplied. This stage cannot change that gate.
