# Novice workflow and agent acceptance

Status snapshot: 2026-10-18. Run the suite from the repository root with `./.venv/bin/python -m unittest discover -s tests -v`; it creates and removes only uniquely named `concept-accept-*` and `concept-agent-nested-*` Elasticsearch fixtures. See [`agent-api.md`](agent-api.md) for the API contract and [`agent-research.md`](agent-research.md) for official-source design decisions.

## Required acceptance gates

1. **Beginner path:** quickstart identifies useful fields, the user confirms them, and a query can be previewed and graded without editing numeric weights or raw DSL.
2. **Human feedback:** saved query identity is exact and stable; rewording does not transfer grades. Positive, explicit negative, unjudged, and pin state remain distinct. Pins affect placement only, never the objective score.
3. **Concept explanation:** draft fields are schema-validated; aliases, related concepts, exclusions, snippets, and source evidence are represented honestly. No snippet may be fabricated across separate scalar values or imply that a related/negated mention is a confirmed factual relationship.
4. **Read-only host tools:** only bounded, allowlisted schema/sample/preview/document/diagnostic actions run. Verify original source text for fetched docs, nested dotted fields, filtered-out docs, and ad-hoc query scope without inheriting saved labels. No generic HTTP, query DSL, shell, file, browser, Elasticsearch write, save, grade, tune, or deploy tool is exposed to the model.
5. **Agent provider truth:** report SDK availability, sign-in, and inference as separate states. Codex permits only parsed empty resource-discovery metadata under the restricted policy; any data-bearing or unknown native event fails closed. Copilot uses `mode="empty"`, no provider tools, and the `auto` default. Provider calls are bounded, cancelable, scoped, resettable, and do not include credentials.
6. **Trust and robustness:** invalid JSON, foreign corpus/session scope, unsupported fields, prompt injection in document text, malformed drafts, cancellation, timeout, and provider errors do not cause writes or false success. Human adoption is explicit.
7. **Retrieval and evaluation:** baseline and tuned metrics compare the same query split and corpus snapshot. Held-out labels cannot influence selection. Missing validation labels produce a clear train-only warning; no positive training labels reject tuning. Unknown labels use an explicit judged-only metric policy and coverage.
8. **Reproducibility:** concept versions, judgments, and runs persist and reload. Export is versioned and credential-free; Python runtime helper, raw Search API body, and rendered Mustache template must return the same ordered documents for nested fields and saved filters, including escaped query input.
9. **Regression and integrity:** preserve the previous 30-query evaluation (Q01–Q10 across BM25/vector/hybrid), code-RAG behavior, and source-index contents. Fixture cleanup is limited to the test-owned index.
10. **Distribution and UI:** build/install the wheel in an isolated environment and exercise the installed CLI, HTTP health, and a complete novice flow. Browser acceptance covers creation, preview, judgment, tuning/apply/save/reload, provider path when available, mobile layout, tab state, and zero application JS errors/overflow. Mark mock, real-provider, live-ES, browser, package, and source-integrity evidence separately.
11. **Saved preview settings difference:** pairwise comparison reports accurate settings from the two exact stored snapshots, distinguishes unavailable/malformed from recorded-empty values, escapes and bounds long content, remains available when rank movement is suppressed, and makes no causal or quality-improvement claim. Preserve exact stored-artifact/no-requery behavior and existing comparison guards. See [`saved-run-settings-diff-acceptance.md`](saved-run-settings-diff-acceptance.md).
12. **Tune readiness:** aggregate readiness matches non-stale train/validation judgment selection without Elasticsearch or writes; missing storage is unavailable while a valid empty judgment table means zero; UI explains the next train-label action, handles errors and edit races, and does not promise tune success or quality gains. `/api/concepts/tune` remains authoritative. See [`tune-readiness-acceptance.md`](tune-readiness-acceptance.md).
13. **Tune query coverage:** extend readiness with distinct graded/positive query counts and total current-request-query-list denominators by split, including unlabeled entries and possible unsaved edits, while preserving existing document counts, eligibility, stale handling, privacy, and read-only behavior. UI explains coverage without claiming representativeness or quality and has no minimum-query threshold. See [`tune-query-coverage-acceptance.md`](tune-query-coverage-acceptance.md).
14. **Exact chunk input:** show the exact prefix/trimmed `rag_chunk_text` or structured-field passage sent to vectorization, preserve `_source`, and expose an explicit empty state without model loading or extra Elasticsearch calls. Keep cache-only unavailable input distinct from the hypothetical field-selected whitespace chunk preview; escape content, explain the 512-token limit without claiming tokenizer counts, and pass mobile layout/error/cache regressions. See [`chunk-input-acceptance.md`](chunk-input-acceptance.md).

## Reporting rule

Record the exact command, environment, test count, provider/SDK version, live-vs-mock boundary, and artifact path for each completed gate. `NOT RUN` and skipped gates are not PASS. If a live subscription or service is unavailable, retain deterministic/mocked coverage but label the real-provider proof unavailable; do not replace it with a mock claim.
