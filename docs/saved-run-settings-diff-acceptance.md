## Acceptance criteria

| Gate | PASS when | FAIL when |
|---|---|---|
| Saved input changes | Comparing `match-a` and `match-b` reports each changed saved value for name, description, aliases, related term/relation/weight, excluded terms, corpus title/text fields, filter fields and filters, search mode, result/candidate limits, concept/related weights, and field boosts. Additions, removals, and per-item changes are described accurately. | The summary omits a changed field, invents a value/default, loses list membership, or reads current editor state. |
| Unchanged configuration | Comparing `settings-unchanged-a` and `settings-unchanged-b` explicitly reports that no saved concept settings differ. | Identical saved inputs are presented as changed or the section is empty/ambiguous. |
| Snapshot availability | Comparing missing, explicit empty-object, and malformed concept snapshots (`settings-snapshot-missing`, `settings-snapshot-empty`, `settings-snapshot-malformed`) yields an explicit unavailable/legacy state. Comparing otherwise complete snapshots with an omitted `aliases` key versus explicit `aliases: []` (`settings-aliases-missing`/`settings-aliases-empty`) distinguishes “not recorded” from “recorded empty.” Malformed data does not crash rendering. | Missing or malformed input is silently treated as defaults/empty, or bad data breaks the comparison. |
| Stored-only and privacy boundary | Exactly the two selected `/api/concepts/runs/export` artifacts supply the settings summary. No Elasticsearch request, current-concept fetch, or requery is made. Grades, reasons, and source bodies remain absent. | Any non-selected/current/live source contributes settings, or private run fields are displayed. |
| Honest interpretation | The settings summary remains visible when rank comparison is suppressed (compare `context-mismatch` with `match-a`). The isolated `filter-mismatch`/`match-a` pair has matching UUID, query, mapping, baseline, and search limits, with only actual filter value/fingerprint changed; it must name that filter mismatch and suppress direct movement. | Escaping and bounds | Fixture strings containing HTML remain text and create no `img`/`script` nodes. `settings-long` (2–4 KB strings and 80-item lists across concept fields) renders within documented limits and communicates omitted values/counts. | Markup executes, unbounded output expands the page, or truncation makes values look complete when they are not. |
| Existing comparison behavior | Matched context still shows exact `(index,id)` rank movement; mismatch, baseline/hash/index-identity failures still keep side-by-side snapshots and suppress deltas; pin-only results remain unranked. Existing detail and JSON download behavior remains available. | Settings differences change identity/rank rules, mismatch guards regress, or existing detail/export flow breaks. |
| Layout and regression | At 390px, document width does not exceed viewport width; Node syntax, the full Python suite, isolated wheel/install + CLI, and required targeted checks pass. | Required check fails without a documented code fix and rerun, or a gate is incorrectly recorded PASS after skip/failure. |

## Disposable fixture

`tests/run_preview_comparison_fixture.py` creates a temporary SQLite database containing synthetic saved runs, serves it on a dynamically allocated loopback port, and removes the database on shutdown. It does not inspect a user database or credentials and does not connect to Elasticsearch. Use `match-a`/`match-b` for a broad concept-settings change with rank comparison still eligible, `settings-unchanged-a`/`settings-unchanged-b` for identical settings, `context-mismatch`/`match-a` for visibility of settings, effective-filter, mode, and limit changes while rank movement is suppressed, `filter-mismatch`/`match-a` for the isolated actual-filter mismatch, the `settings-snapshot-*` runs for absent/empty/malformed snapshot history, `settings-aliases-missing`/`settings-aliases-empty` for omitted versus explicitly empty values inside otherwise complete snapshots, and `settings-long` for output bounds. Existing mismatch, identity, pin, source-hash, and baseline fixtures remain available.

Keep the local fixture port dynamic. Do not use or stop processes on ports 8765/8766. Test only synthetic values in this fixture.

## QA iteration notes

An early fixture version changed mode and result limits in `match-a`/`match-b`, which correctly suppressed rank movement and made it unsuitable for the matched-rank regression. The fixture was corrected so that pair keeps mode/size/candidate size and actual filters equal while concept content and weights change. Separate `context-mismatch` and `filter-mismatch` cases now test visible settings diffs with movement suppressed; the latter changes only the actual filter and fingerprint among comparability fields. Initial UI review also identified omitted title/filter fields and absent-versus-empty list handling; the implementation added those paths and a clear incomplete-snapshot note before the final browser rerun. All corrected cases above passed.
