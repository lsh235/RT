## Test iteration notes

The first focused run exposed two assertion mistakes in the new test itself: the response nests each preview under `results[].preview`, and the first browser-heading selector also collected the baseline/candidate subheadings. The test assertion was corrected to follow the response shape; the browser selector was narrowed to direct card headings. The first stale-request fixture asserted after 300ms while its route delay was 500ms; it was corrected to await `page.waitForResponse()` and `response.finished()` before asserting. A separate race fixture now awaits both the ordinary-preview response and the delayed group response before asserting which content remains. The first isolated packaging run found the version mismatch above; the source version was corrected and the packaging check rerun successfully. These issues were corrected and the final focused run and browser flow passed.

The synthetic browser fixture is checked in at `tests/cycle17_information_need_preview_browser.js`; its exact invocation and scope are recorded in the UI gate above. Repeatable HTTP and source-level checks are in [the acceptance test module](../tests/test_concept_information_need_preview_acceptance.py).
