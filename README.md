# Elasticsearch RAG 튜닝 작업대

Elasticsearch에 저장된 문서를 직접 검색하고, 검색 결과와 근거를 살펴보며 설정을 비교하는 로컬 웹 도구입니다. Jira·Confluence 같은 업무 문서에서 어떤 검색어와 필드가 기대한 문서를 찾는지 확인하려는 개발자와 검색 담당자를 위한 실험 작업대입니다.

이 프로젝트는 **기존 Elasticsearch 인덱스 검색·평가·설정 비교**와 **계정별 개인 지식 보관·재색인**을 한 로컬 작업대에서 다룹니다. 개인 지식은 문자·문단·고정 토크나이저 청크 정책으로 로컬 SQLite에 보관하고, 명시적으로 요청한 작업이 성공적으로 검증된 뒤에만 그 계정의 Elasticsearch 별칭을 교체합니다. 기존 공유 인덱스의 임의 문서를 자동으로 재분할하거나 재색인하지 않으며, RAG 답변 생성 서비스도 제공하지 않습니다. 작은 표본이나 모의 실행 결과만으로 전체 코퍼스의 검색 품질이나 운영 적합성을 판단할 수 없습니다.

## 개발 완료 목표

현재 구현 작업 기준은 **R07 / v1.12.0**이며, [1.5.0 기준선](docs/roadmap/oss-readiness-plan.md) 이후 공개 저장소 준비와 로컬 개인 지식 개선을 단계별로 진행 중입니다. 전체 단계와 완료 게이트는 [개선 계획](docs/roadmap/oss-readiness-plan.md) 및 [진행 기록](docs/roadmap/progress.json)에 있습니다. Cycle 45–48 기능은 아직 전체 완료로 판정하지 않았습니다. 이 계획은 로컬 앱 계정 하나가 직원 소유자 한 명에 대응하고, 앱을 loopback/local 환경에서 사용하며, 개인 지식을 공유 일반 Elasticsearch 인덱스와 분리해 취급한다는 가정에 기반합니다.

## 빠른 시작

필요한 것: Python 3.10 이상, 브라우저, 연결할 Elasticsearch 주소. BM25 검색은 추가 임베딩 패키지 없이 사용할 수 있습니다. 계정 부트스트랩은 로컬 관리자를 만듭니다.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m es_rag_tuner auth bootstrap-admin
.venv/bin/python -m es_rag_tuner
```

브라우저에서 <http://127.0.0.1:8765>를 열고 앞 단계에서 만든 계정으로 로그인합니다. 서버는 loopback 주소에만 바인딩됩니다. 종료하려면 실행한 터미널에서 `Ctrl+C`를 누릅니다.

아직 Elasticsearch가 없다면 다음 예시로 로컬 단일 노드를 실행할 수 있습니다. 포트는 로컬 호스트에만 공개됩니다. 보안을 끈 설정은 이 loopback 전용 샘플에서만 사용하세요.

```bash
docker run --name es-rag-local --detach \
  --publish 127.0.0.1:9200:9200 \
  --env discovery.type=single-node \
  --env xpack.security.enabled=false \
  --env 'ES_JAVA_OPTS=-Xms1g -Xmx1g' \
  --volume es-rag-local-data:/usr/share/elasticsearch/data \
  docker.elastic.co/elasticsearch/elasticsearch:9.5.5
```

## 초보자 작업 흐름

### 1. 인덱스를 연결하고 문서를 확인합니다

앱에서 Elasticsearch 주소를 입력합니다. 로컬 예시는 `http://127.0.0.1:9200`입니다. 원격 서버에는 HTTPS를 사용하세요. 인덱스를 선택한 뒤 **필드와 예시 확인**으로 매핑과 일부 문서를 살펴봅니다. 필드 제안은 매핑을 바탕으로 한 후보이지, 의미상 적합성을 보증하지 않습니다. 이 단계의 검색과 조회는 기존 인덱스를 읽습니다. 샘플 인덱스 가져오기는 별도 작업이며 새 인덱스를 만듭니다.

### 2. 검색할 개념과 질의를 저장합니다

개념에는 찾으려는 내용, 다른 표현과 관련 용어, 검색할 텍스트 필드, 선택 필터와 질의를 기록합니다. 먼저 BM25 미리보기를 실행하고 기준 결과와 개념을 적용한 결과를 비교해 제목, 발췌, 일치 근거와 점수를 살펴보세요. 검색 점수는 관련성 확률이 아닙니다.

각 저장 질의는 **학습용(train)** 또는 **별도 확인용(validation)**으로 구분할 수 있습니다. 찾을 문서를 판단할 때 질의별 결과에서 사람이 관련도를 기록합니다.

- `0`은 무관하다고 판단한 문서입니다.
- `1–3`은 관련 있다고 판단한 문서입니다. Cycle 44의 긍정 대상 목록에는 이 등급만 포함됩니다.
- 등급이 없는 상태는 아직 판단하지 않은 상태입니다. 이를 `0`으로 간주하지 않습니다.

질의·개념을 저장한 뒤 학습용 질의에서 문서 하나 이상에 긍정 등급을 기록하면 설정 비교를 시작할 수 있습니다. 준비 안내는 평가가 준비되었는지 보여주는 상태이며, 튜닝 성공이나 검색 품질을 보장하지 않습니다.

### 3. 설정을 비교합니다

**설정 비교**는 저장된 학습용 평가 자료를 기준으로 BM25 설정을 비교합니다. 검증용 질의는 설정 조정에 쓰이지 않으며, 별도로 결과를 확인하는 용도입니다. 따라서 학습과 검증 결과를 한 집합처럼 합쳐 보지 마세요.

결과의 `K`는 해당 튜닝 실행에 저장된 결과 크기 설정입니다. 아래의 긍정 대상 확인은 실행 당시 저장된 판단과 순위 스냅샷만 비교합니다. 현재 Elasticsearch를 다시 검색해 과거 결과를 재구성하지 않습니다.

### 4. 조정 후 상위 결과에서 빠진 긍정 판단 문서를 확인합니다

튜닝 결과의 **조정 후 상위 결과에서 빠진 긍정 판단 문서** 영역은 학습용과 검증용을 나누어 보여줍니다. 검증용은 학습에 사용하지 않은 별도 확인입니다.

- 대상은 실행에 저장된 판단 중 등급 `1–3`인 항목입니다. `0`, `null` 또는 잘못된 등급은 긍정 대상에 포함하지 않습니다.
- 문서 동일성은 `(질의 ID, 인덱스, 문서 ID)`로 구분합니다. 문서 ID가 같아도 인덱스나 질의가 다르면 별도 항목입니다.
- 저장된 조정 결과에서 순위가 `K` 이하이면 상위 K개 안에 포함된 것입니다. 순위가 K보다 뒤이거나 저장 결과에 없으면 이 목록에 나타납니다. 가능한 경우 기준선에서의 순위도 함께 표시됩니다.
- 각 구분은 최대 20개까지 표시하고, 나머지 개수를 따로 알립니다. 유효한 스냅샷이 없거나 형식이 맞지 않으면 “누락 없음”으로 처리하지 않고 판정할 수 없다고 표시합니다. 그 구분에 긍정 등급이 없는 경우에도 “누락 없음”을 뜻하지 않습니다.

이 목록은 **저장된 튜닝 결과의 상위 K개와 기록된 긍정 판단의 차이**를 보여주는 점검 항목입니다. 판단하지 않은 문서나 아직 기록되지 않은 관련 문서는 알 수 없으므로 코퍼스 전체 재현율, 인덱스에 문서가 있는지, 다른 질의에서 찾을 수 있는지, 답변 품질을 뜻하지 않습니다. 차이 개수도 통계적 유의성이나 운영 품질의 증거가 아닙니다.

### 5. 필요한 경우 정확한 문서를 수동 진단으로 전달합니다

목록의 **정확한 문서 진단으로 전달**을 누르면 저장 질의와 문서의 인덱스·ID가 수동 문서 영역에 입력됩니다. 이 전달 동작은 진단 요청을 보내거나 평가 등급을 저장하지 않습니다. 입력된 값을 확인한 뒤 문서 진단 버튼을 직접 눌러야 합니다. 선택 인덱스나 Elasticsearch 주소, 저장 개념 또는 설정 범위가 바뀌면 이전 보고서의 전달 동작은 비활성화됩니다.

문서 ID를 모르면 제목이나 본문에서 기억나는 단어로 후보를 찾을 수 있습니다. 후보를 고르는 것만으로는 판단이 저장되지 않습니다. 관련도 등급은 결과를 확인한 뒤 사람이 명시적으로 기록해야 합니다.

## 기능 지도

### 공유 Elasticsearch 검색

- **BM25:** 텍스트 필드, 필드 가중치, 필터, 하이라이트와 `_explain` 점수 근거를 살펴봅니다.
- **벡터 검색:** 인덱스에 기록된 임베딩 프로필과 일치할 때 사용합니다. 기존 E5 기본값을 유지하며, E5 또는 multilingual MiniLM 로컬 프로필을 선택할 수 있습니다.
- **하이브리드:** BM25와 벡터 결과 순위를 RRF 방식으로 합칩니다. 서로 다른 방식의 점수를 직접 비교하지 않습니다.
- **개념 미리보기와 평가:** 기준 결과와 개념 적용 결과, 질의별 판단과 지표를 비교합니다. 설정 비교는 현재 BM25 모드만 지원합니다.
- **청크 미리보기:** 문자, 문단 또는 고정 E5 토크나이저로 개인 지식의 청크와 원문 오프셋을 확인합니다. 토크나이저가 준비되지 않은 경우 토큰 청킹은 실행되지 않습니다.

로컬 임베딩을 사용하려면 선택 패키지를 설치합니다. 설치만으로 모델 파일을 받지는 않습니다. E5(`intfloat/multilingual-e5-large`, 1024차원)와 multilingual MiniLM(`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, 384차원)을 선택할 수 있으며, 앱은 선택한 모델의 캐시 준비 상태와 레시피를 표시합니다. 캐시되지 않은 모델을 받을 때는 동의 안내와 예상 다운로드를 확인하세요. 프로필이 다른 기존 벡터는 선택한 모델과 호환된다고 가정하지 않습니다. 문서 임베딩은 선택 인덱스의 `rag_embedding` 필드를 부분 업데이트하므로 인덱스와 권한을 먼저 확인해야 합니다. 자세한 계약과 검증 범위는 [API 계약](docs/api-contract.md) 및 [v1.11.0 acceptance](docs/acceptance/v1.11.0.md)를 참고하세요.

BM25, 벡터, RRF 하이브리드 검색은 후보 풀과 최종 Top-K를 따로 설정합니다. 결과에는 구체 인덱스/문서 ID, lane별 순위와 원점수, RRF 및 재순위화 근거가 표시됩니다. 각 점수는 보정되지 않은 진단값이며 관련도 확률이 아닙니다. 선택형 로컬 재순위화를 사용하려면 `.venv/bin/python -m pip install -e '.[reranker]'`로 추가 패키지를 설치하고, 화면에서 동의한 뒤 고정된 BAAI/bge-reranker-v2-m3 모델 파일(약 2.3 GB)을 준비합니다. 일반 검색은 이 모델을 다운로드하지 않습니다. 재순위화를 켰는데 런타임이나 캐시가 준비되지 않은 경우 요청은 명시적 오류로 끝납니다. 이 통합만으로 검색 품질 향상을 주장하지 않습니다. 자세한 내용은 [v1.12.0 acceptance](docs/acceptance/v1.12.0.md)와 [API 계약](docs/api-contract.md)을 참고하세요.

```bash
.venv/bin/python -m pip install -e '.[semantic]'
```

벡터 검색 가능 여부는 Elasticsearch 배포판과 매핑에 따라 다릅니다. 벡터가 준비되지 않으면 BM25부터 사용할 수 있습니다.

### 개인 지식 라이브러리

문서와 청크를 로컬 SQLite에 보관하고 FTS5/BM25로 검색하는 기능입니다. 저장된 개인 문서는 문자·문단·고정 E5 토크나이저 정책으로 분할할 수 있습니다. 청크 미리보기는 읽기 전용이며, 재색인은 명시적인 작업으로 시작합니다. 작업은 진행 상태를 저장하고 취소·실패·프로세스 재시작 뒤에 확인하거나 재시도할 수 있습니다. 새 Elasticsearch 세대의 청크 수와 식별을 확인한 다음 계정별 별칭을 바꿉니다. 검색 상태와 작업 기록은 [개인 지식 API/저장 계약](docs/api-contract.md)에 설명합니다. R05의 게이트와 증거는 [v1.10.0 acceptance](docs/acceptance/v1.10.0.md)에 있습니다.

```bash
.venv/bin/python -m pip install -e '.[private-vector]'
```

벡터 동기화는 추가 설치와 화면 내 명시적 다운로드 동의가 필요합니다. 선택한 프로필의 모델 파일과 tokenizer가 처음에 캐시될 수 있습니다. 현재 기본 E5 모델은 약 2.24 GB이며 크기가 작은 대체 프로필은 앱의 선택 화면에 표시되는 안내를 확인하세요. BM25 동기화와 검색은 모델을 다운로드하지 않습니다. 벡터 프로필은 계정별로 저장되며 프로필 변경 후 벡터를 다시 동기화해야 합니다.

### 선택 기능: AI 개념 도우미

AI 도우미는 Codex 또는 GitHub Copilot SDK를 사용합니다. Codex SDK는 Python 3.10 이상, Copilot SDK는 Python 3.11 이상이 필요합니다. 아래 `.[agents]` 설치는 현재 Python 버전에서 지원되는 SDK를 설치하므로 Python 3.10에서는 Copilot SDK가 설치되지 않습니다. 사용할 provider 계정의 인증이 필요합니다.

```bash
.venv/bin/python -m pip install -e '.[agents]'
```

도우미는 기존 Codex desktop 또는 Copilot 채팅을 재사용하지 않습니다. 질의나 선택한 문서 필드 등 필요한 문맥이 provider로 전송될 수 있습니다. 제안·요약·진단은 검증된 사실이나 검색된 답변이 아니며, 답변 생성 시스템도 아닙니다. 사용자가 검토한 뒤 명시적으로 저장하거나 적용해야 합니다. 세부 내용은 [AI API 안내](docs/agent-api.md)와 [AI 연구 및 제한](docs/agent-research.md)을 참고하세요.

## 개인정보와 보안

첫 실행 전에 로컬 계정을 부트스트랩합니다. 계정별 개념, 평가, 실험 기록, 세션과 개인 지식 데이터는 로컬 SQLite에 저장됩니다. 기본 위치는 `~/.local/share/es-rag-workbench/`입니다. `ES_RAG_CONCEPT_DB`로 상태 DB 경로를, `ES_RAG_MODEL_CACHE`로 모델 캐시 경로를 바꿀 수 있습니다.

Elasticsearch 주소, 인덱스와 인증 정보를 브라우저에서 입력합니다. 앱 계정 DB에는 Elasticsearch 비밀번호나 API 키를 저장하지 않습니다. 연결된 Elasticsearch 인덱스는 계정 간에 공유될 수 있으며 접근은 Elasticsearch 자격 증명의 권한을 따릅니다. 앱 계정 분리는 Elasticsearch 보안 기능(DLS 등)이 아니고, 같은 호스트의 다른 프로세스나 앱 데이터 디렉터리에 접근할 수 있는 사용자로부터의 격리도 아닙니다. 앱을 공개 네트워크에 노출하거나 reverse proxy 뒤에 배포하지 마세요.

## 개인 지식 파일 가져오기와 백업

로그인한 계정의 **내 지식** 화면에서 `.txt`, `.md`, `.csv`, `.jsonl` 파일을 미리 보고 개인 보관함에 가져올 수 있습니다. CSV와 JSONL은 제목, 내용, 선택적 출처 필드를 직접 지정합니다. 중복 문서는 각 행마다 건너뛰기 또는 교체를 선택하고, 저장에 실패한 행은 이유와 함께 확인하세요. 일부 행이 실패해도 이미 성공한 행은 보관되므로 결과 목록을 확인합니다. 계정 한도는 문서 100개, 저장 내용 20 MiB, 파일 및 개별 문서 1 MiB입니다.

가져온 텍스트와 Markdown은 실행되지 않는 데이터로 처리합니다. 문서를 편집하거나 삭제하면 개인 Elasticsearch 검색 상태가 오래된 것으로 표시되며, 화면에 성공적인 동기화까지의 경계가 유지됩니다. 최신 문서로 검색하려면 **BM25 동기화 / 재시도**를 명시적으로 선택하세요. 내보내기는 로그인 계정의 문서와 개인 평가가 든 JSON 백업을 다운로드합니다. 복원 전에 백업을 미리보고 각 충돌을 건너뛸지 교체할지 선택합니다. 복원 파일은 최대 128 MiB까지 선택할 수 있으며, 실제 복원 가능 내용과 사용량은 미리보기에서 확인합니다. 이 파일 흐름은 개인 보관함만 다루며 공유 인덱스는 변경하지 않습니다.

## 범위와 한계

- Recall@k, MRR@k, nDCG 등의 지표는 기록된 질의, 판단 문서, 데이터 분할과 cutoff에 대한 값입니다. 미평가 문서는 무관 문서가 아닙니다.
- 표본이 작거나 판단이 불완전할 수 있습니다. 지표나 긍정 대상 목록만으로 일반화, 통계적 유의성, 전체 코퍼스 재현율 또는 운영 준비 상태를 주장하지 마세요.
- 검색 순위 평가는 생성된 RAG 답변의 정확성, 완전성, 인용 근거를 평가하지 않습니다.
- 개인 지식 재색인은 공유 인덱스에 적용되지 않으며, synthetic fixture와 로컬 lifecycle 테스트는 실제 코퍼스의 검색 품질을 증명하지 않습니다.
- 개인 계정의 로컬 분리는 공유 Elasticsearch 인덱스의 접근 제어를 대체하지 않습니다.

샘플 Jira 실험의 결과와 실행 조건은 [첫 마일스톤](docs/first-milestone.md)에 있습니다. 이것은 재현 가능한 샘플 평가이지 외부 코퍼스의 결과가 아닙니다. 실제 인덱스에 적용하기 전에 대표 질의와 기대 문서를 준비하고, 같은 조건에서 설정 전후를 비교하세요.

통합 검증은 다음 명령으로 실행할 수 있습니다.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

전체 검사에는 로컬 Elasticsearch와 provider 계정이 필요한 테스트, 결정적 모의 검사가 함께 있습니다. 해당 의존성이 없는 환경의 실패나 건너뜀은 서비스 결함 판정도 전체 PASS 증거도 아닙니다. 실행 환경과 판정 범위는 [통합 acceptance 기록](docs/agent-acceptance.md)을 확인하세요.

## 문제 해결

- **로그인할 계정이 없습니다:** `.venv/bin/python -m es_rag_tuner auth bootstrap-admin`을 실행해 최초 관리자를 만듭니다. 초기화된 DB에서는 다시 부트스트랩할 수 없습니다.
- **Elasticsearch에 연결되지 않습니다:** 주소, 포트, 인증 정보와 서버 상태를 확인하세요. 앱과 Elasticsearch가 서로 다른 컨테이너나 호스트에 있으면 앱 컨테이너의 `127.0.0.1`은 Elasticsearch가 아닙니다.
- **필드가 검색되지 않거나 결과가 비어 있습니다:** 선택 인덱스의 매핑과 검색 가능한 텍스트 필드를 확인하세요. 검색 결과에 문서가 없다고 해서 문서가 인덱스에 없다고 단정할 수는 없습니다.
- **설정 비교를 시작할 수 없습니다:** 저장된 학습용 질의에서 관련 문서 하나 이상에 `1–3` 등급을 기록하고 저장했는지 확인하세요. 검증용 판단만으로는 설정 조정을 시작하지 않습니다.
- **긍정 문서가 튜닝 결과 목록에 나타납니다:** 해당 실행의 저장된 상위 K 스냅샷과 질의·인덱스·문서 ID를 확인하세요. 표시된다는 것은 기록된 긍정 판단이 그 실행의 조정 결과 상위 K에 없었다는 뜻입니다. 코퍼스 부재를 뜻하지 않습니다.
- **벡터 검색이 준비되지 않습니다:** BM25부터 사용하고 벡터 매핑, 저장 벡터, 선택 패키지와 모델 캐시를 점검하세요. 배포판에 따라 dense vector/kNN 지원이 다릅니다.
- **모델 다운로드가 큽니다:** 공유 문서 임베딩과 개인 지식 벡터 동기화는 별도 선택 기능입니다. 각 기능의 동의 안내와 캐시 용량을 확인한 뒤 시작하세요. 설치만으로 모델을 받지는 않습니다.
- **샘플 지표만 좋습니다:** 실제 코퍼스의 대표 질의와 관련 문서 판단을 추가하고 같은 데이터 분할과 cutoff로 다시 비교하세요.
